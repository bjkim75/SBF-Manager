# Kiro 요구사항 대비 구현 갭 분석

기준: 첨부 Kiro 요구사항 1~15와 현재 SBF Workbench 구현 및 기존 Spec 비교.

| 영역 | 기존 구현 | 이번 추가 | 후속 백엔드 필요 |

| 마스터 표 | 검색, 도메인·Depth 필터, 다중 선택, 상세 | 열 표시 설정·초기화 | 전체 1,172/1,182행 서버 페이지네이션 |

## 이번 구현 범위

- 변경요청 다중 항목과 요청 분야, 30분 편집 잠금 표시 추가
- 알림함 및 읽음/안읽음 상태 추가
- 마스터 열 설정과 초기화 추가
- 버전 목록에서 v2.4/v2.5 CSV 다운로드 및 마스터 필터 결과 CSV 분리
- SBF 마스터 탐색성 개선 설계 추가: milestone 필터, 정렬, 컬럼 고정
- 요청자 관점 상태 배지 설계 추가: 수정중, 삭제 대기, 보완 필요, 반영 완료
- 작업 완료 결과 상세 설계 추가: 과제ID/요구사항ID 변경 전후와 SBF/Jira 반영 결과 확인

## 제한과 안전 처리

현재 앱은 프론트엔드 프로토타입이므로 전체 Excel 행·사용자·요청 상태를 영속 저장하지 않는다. 내부 `1. IA` 전체 데이터가 브라우저 공개 자산에 복제되지 않도록 차단했으며, 배포도 수행하지 않았다. 전체 버전 CSV는 향후 인증된 서버 API가 권한을 확인한 뒤 스트리밍 생성해야 한다.

## 2026-08-14 추가 검토 메모

- SBF 마스터의 탐색 UX는 Excel 사용성을 따르되, 웹에서는 `필터`와 `보기 옵션`을 분리해 사용자가 현재 조건을 이해하기 쉽게 한다.
- milestone은 원본 IA의 일정/단계 판단에 직접 쓰이는 컬럼이므로 기본 필터로 승격한다.
- 컬럼 고정은 임의 컬럼 선택보다 프리셋 방식으로 시작한다. 초기값은 업무 식별성을 위해 `업무ID까지 고정`이 적합하다.
- 변경요청 상태는 요청자가 이해하는 문구로 SBF 마스터 업무ID 옆에 표시한다. 삭제 요청은 실제 반영 전까지 행을 숨기지 않고 `삭제 대기`로 표시한다.
- 과제ID/요구사항ID 변경 완료는 신규 메뉴보다 기존 `내 요청`과 `처리 업무`에서 완료 결과 상세로 연결하는 것이 메뉴 복잡도를 줄인다.

- 2026-08-14 추가: SBF 마스터의 업무ID 상태 배지는 예시가 아니라 현재 등록된 변경요청의 대상 업무ID와 연결되도록 조정한다. 신규 등록 요청처럼 원본 IA에 아직 없는 업무는 마스터 행에 배지가 표시되지 않는다.

- 2026-08-14 추가: SBF 반영 작업은 Depth 일부 필드가 아니라 대상 업무ID의 IA 전체 필드를 변경 전/후로 보여주고 변경 후 값을 직접 수정하는 구조로 보강한다.

- 2026-08-14 추가: SBF 마스터에서 변경접수 건만 보기 radio를 제공하여 처리 업무에 등록된 변경작업 대상 업무ID만 빠르게 확인할 수 있게 한다.

- 2026-08-14 추가: 같은 업무ID에 SUB ID가 여러 개일 때 변경요청 배지가 중복 표시되지 않도록 업무ID+SUB ID 기준으로 매칭한다.

- 2026-08-14 추가: 변경요청 화면에서 업무ID만 입력하면 복수 SUB ID 업무를 정확히 식별할 수 없으므로 SUB ID 입력 컬럼을 추가한다.

## 2026-08-14 처리업무 검토 상세 흐름 보완
- 기존 처리 업무 화면은 상태 버튼 중심이라 검토자가 어떤 요청 내용을 보고 보완/승인/반려를 결정하는지 흐름이 약했다.
- `검토 시작`은 요청 상세 창을 여는 행위로 보완하고, 상세 창에서 요청 원문 확인, 검토자 기본정보 보정, 보완 요청/승인/반려 결정을 수행한다.
- 승인 이후에만 SBF 반영 작업으로 진입하도록 하여 `요청 검토`와 `SBF 수정 반영` 단계를 분리한다.

## 2026-08-14 SBF 마스터 sort 컬럼 숨김
- SBF 마스터 화면에서 Excel 내부 정렬용 `sort` 컬럼은 사용자가 직접 확인할 업무 속성이 아니므로 표시하지 않는다.
- 정렬 방향 컨트롤의 기본 기준은 화면에 표시되는 `업무ID`로 변경한다. 따라서 필터값 초기화 상태의 오름차순/내림차순은 업무ID 기준으로 동작한다.

## 2026-08-14 SBF 마스터 상태 배지 색상 통일
- SBF 마스터의 업무ID 옆 상태 배지는 변경요청/내 요청 목록의 상태와 동일한 의미를 가지므로 같은 폰트색/배경색 체계를 적용한다.

## 2026-08-14 변경요청 전체 IA 필드 입력 보완
- 기존 변경요청 표는 업무ID, SUB ID, 변경 전/후 텍스트 중심이라 SBF IA 전체 컬럼 변경 요청을 구조적으로 표현하기 어려웠다.
- 신규 요청은 IA 전체 컬럼을 빈 값에서 작성하고, 수정/삭제/매핑 변경은 업무ID + SUB ID로 현재 SBF 행을 불러온 뒤 요청 변경값을 수정하는 방식으로 보완한다.
- 이 요청 변경값은 검토 상세와 SBF 반영 작업의 초기값으로 이어지는 것이 자연스럽다.

## 2026-08-14 변경요청 기준값 불러오기 실제 데이터 연결
- 변경요청의 기준값 불러오기는 최신 공식 SBF 마스터 데이터에서 업무ID + SUB ID로 행을 찾아 전체 cell 값을 채우는 방식이어야 한다.
- 기존 구현은 v2.5 items에 직접 의존하고 있어 대상 버전과 화면 기준 데이터가 달라질 수 있으므로 version 기준 데이터 선택 로직을 추가한다.
- 업무ID/SUB ID 조회는 파싱된 필드와 원본 IA cell 값을 모두 확인하도록 보강하여, 원본 엑셀 행은 존재하지만 변환 필드 기준 비교에서 누락되는 경우를 방지한다.

## 2026-08-14 SBF 마스터 검색 포커스 유지
- SBF 마스터 검색창은 업무ID를 빠르게 입력하는 사용성이 중요하므로, 검색어 입력마다 input 포커스가 다른 곳으로 이동하지 않아야 한다.
- 구현상 내부 함수 컴포넌트를 JSX 컴포넌트로 재마운트하지 않고 동일 렌더 트리에서 유지하도록 보완한다.

## 2026-08-14 변경요청 업무ID placeholder 개선
- 업무ID 입력란에 B2036만 보이면 비활성 기본값처럼 오해될 수 있으므로 ex: B2036 placeholder로 예시임을 명확히 한다.

## 2026-08-14 SBF 마스터 업무ID 상세 drawer 보완
- 업무ID 클릭 상세는 요약 계층 정보보다 원본 IA 전체 열 확인 목적이 크므로, 선택 행의 전체 cell 값을 표시하는 drawer로 변경한다.
- 전체 열이 많기 때문에 drawer는 세로 스크롤, 표 영역은 가로 스크롤을 지원해야 한다.

## 2026-08-14 SBF 마스터 상세 placeholder 상태 배지 제거
- 상세 drawer의 파란 점과 ??는 원본 상태 placeholder가 badge로 노출된 것으로, 현재 기획 의미가 없으므로 숨긴다.

## 2026-08-14 처리업무 기본 view 변경
- 처리업무는 여러 요청의 상태와 반영 여부를 비교하는 목적이 강하므로 기본 view를 카드형에서 리스트형으로 변경한다.

## 2026-08-14 내 요청 사용자 필터 보완
- 변경요청 메뉴와 내 요청 메뉴가 같은 전체 목록을 표시하고 있어 요청자 메뉴의 의미가 약했다.
- 내 요청은 테스트 로그인 사용자 김서현 기준으로 requester 필터를 적용하고, 변경요청은 전체 요청 현황으로 유지한다.

## 2026-08-14 변경요청 대상 도메인 마스터 연동
- SBF 마스터 도메인 필터는 실제 마스터 데이터 기반인 반면 변경요청 대상 도메인은 하드코딩되어 있어 목록 차이가 발생했다.
- 변경요청 모달도 최신 공식 SBF 마스터 데이터에서 도메인 목록을 생성하도록 보완한다.

## 2026-08-14 업무ID 상세 변경요청 prefill
- 상단 + 변경요청은 신규/일반 요청 진입점이고, 업무ID 상세 drawer의 변경요청 작성은 대상 업무를 이미 알고 있는 진입점이다.
- 후자의 경우 선택한 IA 행의 업무ID, SUB ID, 도메인, 전체 cell 값을 요청서에 자동 채워 사용자가 변경 필요한 값만 수정하도록 보완한다.

## 2026-08-14 신규 변경요청 버튼명 통일
- 같은 빈 변경요청 창을 여는 버튼은 화면 위치와 관계없이 새 변경요청으로 통일한다.
- 업무ID 상세에서 선택 행을 기반으로 여는 버튼은 기능 차이가 있으므로 변경요청 작성을 유지한다.


## 2026-08-14 처리 업무 Workflow 버튼 활성화

처리 업무의 버튼은 단순 상태 변경 버튼 모음이 아니라 `요청 검토 → SBF 반영 → Jira 확인 후` 단계 진행을 안내해야 한다. 따라서 현재 상태에 해당하는 단계만 강조하고, 이전/다음 단계는 비활성화한다. SBF 반영 완료는 목록에서 누르는 버튼이 아니라 SBF 반영 작업 화면에서 전체 IA 필드를 수정한 뒤 완료하는 흐름으로 제한한다.

## 2026-08-14 요청번호 상세 drawer

내 요청 메뉴의 요청번호는 요청자가 본인이 제출한 내용을 확인하는 핵심 링크다. 기존 구현은 작업 완료 상태에서만 완료 결과 상세를 열어, 검토 중/보완 요청/승인 상태의 요청 내용을 확인할 수 없었다. 요청번호 클릭 시 항상 우측 drawer로 요청 상세를 표시하고, 완료 건은 drawer에서 완료 결과 상세로 이어지게 수정한다.

## 2026-08-14 반려/보완 요청 재요청

반려와 보완 요청은 요청자에게 수정 후 다시 접수하는 동선이 필요하다. 별도 신규 요청으로 만들면 요청번호와 이력이 분리되어 추적이 어려우므로, `내 요청` 상세 drawer에서 수정 내용을 입력하고 같은 요청번호를 `요청 접수` 상태로 되돌리는 방식으로 설계한다.


## 2026-08-14 요청 상세 재요청 drawer 높이 보완
- 수정 후 재요청 화면에서 요청 기본정보 표가 너무 낮으면 요청번호/대상/담당 등 핵심 정보를 확인하기 어렵다.
- 요청 기본정보 표 영역은 화면 높이의 약 30%를 확보하고, drawer 전체는 세로 스크롤을 제공해 하단 재요청 입력까지 자연스럽게 이동할 수 있게 한다.


## 2026-08-14 검토 시작 신청서 원문 재현
- 승인/보완/반려 판단은 요청자가 작성한 원문, 첨부 이미지, 첨부 파일, 전체 IA 필드 변경값을 동일한 흐름에서 볼 수 있어야 한다.

## 2026-08-14 공식 버전과 작업본/template 배포 모델
- SBF 마스터는 공식 배포본만 표시하고 작업본 보기 옵션은 제공하지 않는다.
- SBF 반영 작업 완료 시 공식 v2.5를 직접 수정하지 않고 다음 배포 후보인 작업본/template에 변경 후 IA 전체 필드 값을 저장한다.
- 작업본/template 저장 단위는 요청번호 + 업무ID + SUB ID + beforeRaw/afterRaw snapshot이다.
- 배포관리의 배포 준비 dialog의 실행은 작업본/template을 공식 스냅샷으로 승격하며, 최신 공식 버전 v2.5의 minor를 증가해 v2.6을 생성한다.
- 배포 후 SBF 마스터 기본 버전은 v2.6으로 전환되고, v2.5는 변경하지 않은 읽기 전용 스냅샷으로 보존한다.
- 현재 MVP는 브라우저 메모리 기반으로 동작하며, 새로고침 시 초기 seed로 돌아갈 수 있다. DB/Turso 도입 후 공식 버전, 작업본/template, 배포 이력을 영속화한다.

## 2026-08-14 반복 배포 버전 증가
- 새 배포는 v2.6 단발 생성이 아니라 최신 공식 버전의 minor 번호를 계속 증가시키는 방식이어야 한다.
- 예: v2.5 기준 첫 배포 v2.6, 두 번째 배포 v2.7, 세 번째 배포 v2.8.
- 배포관리 화면의 배포 준비 문구, 배포 dialog, SBF 마스터 기본 대상 버전은 계산된 nextVersion을 사용해야 한다.
- 이전 공식 버전은 변경하지 않고 읽기 전용으로 유지한다.

## 2026-08-14 minor 9 이후 major 증가
- 반복 배포 테스트를 위해 minor는 0~9까지만 증가하고, v2.9 다음은 v3.0으로 전환한다.
- 이후 새 배포는 v3.1, v3.2처럼 동일 규칙을 적용한다.
- 배포관리의 배포 준비 버튼과 배포 dialog는 모두 계산된 nextVersion을 사용해야 하며, v2.6 하드코딩 문구는 제거 대상이다.

## 2026-08-14 SBF 반영 작업 돌아가기
- SBF 반영 작업은 처리 업무에서 진입한 작업이므로 사용자가 작업을 중단하고 이전 메뉴로 돌아갈 수 있어야 한다.
