# SBF 관리 시스템 구현 작업

각 작업은 완료 조건과 테스트가 충족되어야 완료로 간주한다.

## 1. 프로젝트 기반과 공통 구조

- **목적**: 배포 가능한 웹·API·DB 기본 구조 수립
- **범위**: 환경 설정, 공통 오류, 관측성, Asia/Seoul 날짜 유틸
- **요구사항**: NFR-02~05
- **실행**: 프로젝트 생성 → 환경 스키마 → 오류 응답·correlation ID → CI 구성
- **완료 조건**: 개발/테스트/운영 설정 분리, 빌드와 헬스체크 통과
- **테스트**: 설정 누락 실패, 날짜 경계, 빌드 TC

## 2. 데이터베이스와 마이그레이션

- **목적**: 전체 엔티티, 관계, 제약 구현
- **범위**: User~Revision 테이블, 유니크·참조·검색 인덱스
- **요구사항**: SBF-03, SBF-05, MAP-01~02, HIS-01
- **실행**: 스키마 → 제약 → seed → up/down migration
- **완료 조건**: 빈 DB와 기존 DB 모두 마이그레이션 가능
- **테스트**: 복합키 중복, 활성 매핑 중복, revision 복원

## 3. 인증·권한

- **목적**: 역할과 데이터 범위 기반 접근 제어
- **범위**: 조회자·요청자·검토자·SBF 관리자·Jira 담당·시스템 관리자
- **요구사항**: AUTH-01~03, NFR-04
- **실행**: 인증 연동 경계 → RBAC middleware → 조직 범위 필터 → 권한 UI
- **완료 조건**: 서버 API가 모든 권한을 재검증
- **테스트**: 역할×행위×상태 matrix, IDOR 방지

## 4. 기준정보·사용자·조직

- **목적**: 담당자와 코드의 일관된 참조 제공
- **범위**: 사용자, 조직, 역할, 대상사, 요청유형, 상태 코드
- **요구사항**: AUTH-02~03, IMP-05
- **완료 조건**: 유효하지 않은 참조 저장 차단
- **테스트**: 비활성 사용자·조직·코드 검증

## 5. SBF 마스터

- **목적**: 표/계층 조회와 상세 구현
- **범위**: 검색·필터·정렬·페이지·상세 drawer·export
- **요구사항**: SBF-01~05, NFR-01~03
- **완료 조건**: 실제 v2.5 표본으로 필터와 상세가 일치
- **테스트**: 검색 조합, 빈 결과, 동일 업무ID 여러 SUB, 키보드 접근

## 6. IA-L3 매핑

- **목적**: N:N 매핑과 유효기간 관리
- **요구사항**: MAP-01~04
- **실행**: L3 기준 적재 → 매핑 CRUD → 현재/과거 조회 → 논리 해제
- **완료 조건**: IA→복수 L3와 L3→복수 IA 조회 가능
- **테스트**: 중복 활성 매핑, 기간 겹침, 삭제 경고

## 7. 변경요청 작성

- **목적**: 다중 변경항목의 임시저장·제출
- **범위**: 모든 요청 유형, 대상 선택, 자동 before 값, 첨부·근거
- **요구사항**: CR-01~03, CR-07
- **완료 조건**: 한 요청에 여러 대상·필드 저장 및 전후 비교
- **테스트**: 필수값, 중복 요청 경고, 멱등 제출

## 8. 검토와 상태 전이

- **목적**: 보완·승인·반려와 예외 흐름 구현
- **요구사항**: CR-04~06, AUTH-03
- **실행**: 상태 머신 → 역할 guard → 의견 → 재제출 → 알림
- **완료 조건**: 불가능한 전이 차단, 모든 전이 이력 보존
- **테스트**: 정상·반려·취소·중단·재처리 경로

## 9. 마스터 반영과 변경이력

- **목적**: 승인 요청의 안전한 반영과 복원
- **요구사항**: CR-05, CR-08, HIS-01~02
- **실행**: 기준 revision 비교 → 충돌 UI → 원자 반영 → 새 revision·revision
- **완료 조건**: 임의 시점 상태 재구성, 실패 시 무변경
- **테스트**: 동시수정 충돌, rollback, 필드 diff, 논리 삭제

## 10. Excel 가져오기·내보내기

- **목적**: `1. IA` 전용의 검증 가능한 초기 적재
- **요구사항**: IMP-01~08
- **실행**: 파서 → 헤더 매핑 → staging → 검증 → 미리보기 → 승인 commit → 오류 CSV
- **완료 조건**: v2.5 1,172행 처리 결과가 원본과 대조됨; 다른 시트 32개 제외 기록
- **테스트**: 시트 누락, 복합키 중복, Depth 오류, 공백 대상사, 반복 실행, 대용량 rollback

## 11. 대시보드

- **목적**: 요청·품질·Jira 운영 현황 제공
- **요구사항**: SBF-02, CR-06, JIRA-01, NOTI-01
- **완료 조건**: 카드 합계가 필터된 목록과 일치
- **테스트**: 기간·조직·상태 집계와 드릴다운

## 12. 알림과 Jira 수동 관리

- **목적**: 인앱 알림 및 Jira 추적
- **요구사항**: JIRA-01~02, NOTI-01
- **완료 조건**: 완료 시 이슈 키/URL 필수, 실패 재처리 가능
- **테스트**: 이벤트별 수신자, 중복 알림, Jira 실패

## 13. 통합 E2E와 자체 TC

- **목적**: MVP 핵심 여정 1차 검증
- **요구사항**: 전체 MVP 요구사항
- **TC**:
  1. 마스터 화면과 v2.5/1. IA 출처 표시
  2. 업무ID·업무명·L3 검색과 도메인·Depth 필터
  3. 행 선택·전체 선택·상세 drawer
  4. 변경요청 dialog 필수값·임시저장·toast
  5. 대시보드·변경요청·IA-L3·가져오기 메뉴 전환
  6. 상태 badge와 Jira 미반영 표시
  7. 접근 가능한 label·dialog·한국어 metadata
  8. 반응형 레이아웃과 빈 검색 결과
  9. 프로덕션 빌드, TypeScript, 정적 렌더 smoke
  10. v2.5 데이터 품질 기준값 회귀 검증
- **완료 조건**: 차단급 실패 0건, 나머지 실패 원인·조치 기록

## 14. 데이터 이관 검증

- **목적**: 전체 행과 HTML 이력 교차 검증
- **요구사항**: IMP-01~08, HIS-02
- **완료 조건**: v2.5 1,172행, 53열, 업무ID 931개, L3명 공백 21행, 복합키 중복 1건이 검증 보고서와 일치하거나 관리자가 승인한 차이가 설명됨
- **테스트**: source row sampling, 합계·해시, HTML 변경이력 표본 대조

## 15. 운영 문서와 배포 준비

- **목적**: 관리자 운영과 장애 대응 준비
- **범위**: 사용자 가이드, import runbook, 백업·복구, 보존정책, 배포·rollback
- **요구사항**: NFR-04~05
- **완료 조건**: staging smoke와 rollback rehearsal 완료
- **테스트**: 백업 복원, 재처리, 권한 회수, 장애 알림

## 16. 버전별 CSV 내보내기

- **목적**: 선택한 SBF revision을 재현 가능한 CSV로 제공
- **요구사항**: SBF-06, SBF-05
- **완료 조건**: v2.4·v2.5 선택 시 서로 다른 스냅샷과 행 수, 버전 포함 파일명을 사용
- **테스트**: TC-02, TC-05, TC-06

## 17. SBF 마스터 필터·정렬·컬럼 고정 개선

- **목적**: Excel 원본 IA를 웹에서도 빠르게 탐색할 수 있게 한다.
- **범위**: milestone 필터, 필터 결과 정렬, Excel식 컬럼 고정 프리셋
- **요구사항**: SBF-09~11, SBF-02, NFR-01~03
- **실행**:
  1. `milestone` 컬럼 값을 기준으로 필터 옵션 생성
  2. 필터 결과에 정렬 기준·오름차순·내림차순 적용
  3. `고정 없음`, `업무ID까지`, `SUB ID까지`, `도메인까지`, `담당분과까지`, `4Depth까지` 컬럼 고정 프리셋 제공
  4. 가로·세로 스크롤 상황에서 header와 sticky column의 겹침·가독성 확인
- **완료 조건**: 필터와 정렬 조합이 원본 행 수와 일치하고, 고정 컬럼이 AX열 스크롤 중에도 유지된다.
- **테스트**: milestone 필터, 정렬 기준별 asc/desc, sticky column class, 필터 초기화 회귀 TC

## 18. 업무별 변경요청 상태 배지

- **목적**: 요청자가 SBF 마스터에서 특정 업무의 변경 진행 상태를 바로 인지하게 한다.
- **범위**: 업무ID/SUB ID별 변경요청 상태 매핑, 요청자 관점 상태 문구, 삭제 대기 표시
- **요구사항**: SBF-12~13, CR-07
- **실행**:
  1. 처리 중 변경요청과 SBF 업무 행을 업무ID/SUB ID 기준으로 매칭
  2. 내부 상태를 요청자 표시 상태로 변환
  3. 업무ID 옆에 상태 배지 표시
  4. 삭제 요청은 실제 반영 전까지 행을 유지하고 `삭제 대기`로 표시
- **완료 조건**: 변경요청이 걸린 업무가 SBF 마스터에서 누락 없이 표시되고, 상태 배지가 요청자 관점 문구로 보인다.
- **테스트**: 수정중·삭제 대기·보완 필요·반영 완료 배지 표시 TC

## 19. 작업 완료 결과 상세 연결

- **목적**: 과제ID/요구사항ID 변경 완료 후 요청자와 관리자가 동일한 완료 결과를 확인하게 한다.
- **범위**: `내 요청`/`처리 업무`의 완료 건 클릭, 완료 결과 상세, SBF/Jira 결과 표시
- **요구사항**: CR-11~12, HIS-01, JIRA-01~02
- **실행**:
  1. 작업 완료 상태의 요청 행에서 완료 결과 상세를 열 수 있게 한다.
  2. 과제ID와 요구사항ID의 변경 전·후 값을 표시한다.
  3. SBF 반영결과, Jira 반영결과, 처리자, 완료일, 처리 이력을 표시한다.
  4. 요청자 화면은 결과 확인 중심, 관리자 화면은 처리 근거 중심으로 구성한다.
- **완료 조건**: 작업 완료된 과제ID/요구사항ID 변경요청에서 Complete 상세가 열리고, 요청자도 결과를 확인할 수 있다.
- **테스트**: 작업 완료 행 클릭, Complete 상세 필드, 요청자/관리자 진입 경로 TC

### 20. SBF 마스터와 등록 변경요청 연결

- **요구사항**: SBF-12~14
- **범위**: 변경요청 대상 업무ID 저장, SBF 마스터 배지 조회 로직 정리
- **작업**:
  1. 변경요청 등록 payload의 targetBusinessId를 workflowRequests 상태에 저장
  2. 초기 샘플 변경요청에도 실제 대상 업무ID 메타데이터 부여
  3. SBF 마스터 배지를 업무ID 기반 조회로 변경하고 예시 하드코딩 제거
- **테스트**: 업무ID 기반 매칭, 하드코딩 배지 제거, 신규 변경요청 후 마스터 배지 표시 TC

### 21. SBF 반영 작업 전체 필드 표시

- **요구사항**: CR-13
- **범위**: 대상 업무ID 기반 IA 전체 필드 조회, 변경 전/후 전체 필드 편집 UI
- **작업**:
  1. ChangeCompare에서 대상 업무ID에 해당하는 items.raw와 iaHeaders를 사용
  2. 변경 전 전체 필드는 읽기 전용으로 표시
  3. 변경 후 전체 필드는 입력 가능 필드로 표시
  4. 기존 5개 Depth 필드만 보이던 UI 제거
- **테스트**: iaHeaders 기반 전체 필드 렌더링, afterRaw 편집 상태, 기존 SBF 반영 완료 흐름 유지

### 23. 변경요청 배지 중복 표시 방지

- **요구사항**: SBF-16
- **범위**: 업무ID가 복수 SUB ID를 가진 경우 변경요청 배지와 변경접수 필터 중복 표시 제거

  1. 샘플 및 신규 변경요청에 targetSubId 저장
  2. requestMatchesItem 헬퍼로 업무ID + SUB ID 매칭
  3. SBF 마스터 배지와 변경접수 건만 보기 필터에 동일 매칭 기준 적용
- **테스트**: targetSubId, requestMatchesItem, 업무ID 단독 필터 제거 TC

### 24. 변경요청 화면 SUB ID 입력 추가

- **요구사항**: CR-14, SBF-16
- **범위**: 변경요청 모달 표 편집 항목의 대상 식별자 입력 보강
- **작업**:
  1. 변경요청 표에 SUB ID 입력 컬럼 추가

- **테스트**: targetSubId input, FormData 수집, saveRequest 저장 TC
